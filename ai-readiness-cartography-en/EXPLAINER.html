AI-Readiness Cartography

A skill that scores any repository against the AI-Ready Codebase v2 rubric and visualizes the result as a professional technical dashboard. It answers one question with a number: "How friendly is this codebase to coding agents / LLM workflows?"

Deliverables — always all three at once

It never produces just one. Score → visualize → prioritize, in a single pass.

1
JSON scorecard
Raw data with categories A–G, evidence, sub_scores, findings, ROI actions, and large files. Consumable by other tools. (ai-readiness-score.json)
2
Single HTML dashboard
A decision-making instrument panel for humans: score hero · 7-category bar chart · structural map (SVG) · Wins / ROI panel. (ai-readiness-map.html)
3
ROI-ranked action list
Next steps sorted by impact_score / effort_hours. Each item carries a category tag, effort (S/M/L), and a quantified impact.

How it works

auto-score → fill template → open → summarize
STEP 1

Auto-score in Python

scripts/score.py scans the repo with stdlib only and emits per-category scores, findings, and ROI actions as JSON.

→
STEP 2

Fill the HTML template

Copy assets/template.html and slot in the JSON values. Never write from scratch — the design would drift every time.

→
STEP 3

Open in the browser

open on macOS, xdg-open on Linux. If the user says "don't open it," just report the path.

→
STEP 4

Summary report

Total / grade · the 1–2 weakest categories · top 3 ROI actions · the generated file paths — in one paragraph.

# Step 1 — auto-score (no dependencies, Python 3.10+)
python3 ~/.claude/skills/ai-readiness-cartography-en/scripts/score.py <repo-path> \
  --json <output>/ai-readiness-score.json

# Save-location priority: docs/ → .claude/ → repo root (explicit path wins)
E

What the scorer catches vs. what humans supplement

run the script first → supplement on top

Auto — caught by the script

  • AContext coverage ratio of core modules (CLAUDE.md / AGENTS.md)
  • B1·B5Conciseness · cross-references (relative links)
  • C Q1–Q5Five-Question heuristic + MEMORY/ADR presence
  • DARCHITECTURE.md · mermaid · workspace-file detection
  • E1Hallucinated-path verification — every path candidate checked for existence
  • FContext drift (mtime) + CI / hook validation
  • Gevals/ · benchmarks/ directories + telemetry hints

Manual — supplemented in depth

  • B2–B4The real depth of quick commands · key files · hidden patterns
  • CThe actual depth of tribal knowledge (heuristic-pass ≠ truly there)
  • E2The quality of the independent critic review
  • E4The quality of prompt / workflow tests
  • After receiving the JSON, the LLM supplements manual items or reflects them in the charts.
E1 · top priority
Zero hallucinated paths is the Meta standard. If a context file points at a path that doesn't exist, even one is an immediate fix action. Unverified context is more dangerous than no context at all.
