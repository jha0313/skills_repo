02

Tool ① claude-md-improver

audit skill — quality report → approval → targeted updates
SKILL
claude-md-improver
Audit, evaluate, and improve CLAUDE.md across a codebase
tools: Read · Glob
Grep · Bash · Edit

Finds every CLAUDE.md in the repo, scores it against quality criteria, and outputs a quality report first — then, with your approval, makes minimal targeted edits. The goal: give Claude Code optimal project context.

⚠ This skill writes to CLAUDE.md files — but only after the report and your approval
5-phase workflow
1
Discovery
Collect all CLAUDE.md · .claude.local.md · global / package-level files via find. Monorepos auto-discover parent directories.
2
Quality Assessment
Evaluate each file against 6 criteria and cross-reference with the actual codebase (do commands run? do referenced files exist? is the architecture accurate?).
3
Quality Report
Always before any edit, output the score report: summary + per-file criterion scores + issues + recommended additions.
4
Targeted Updates
Only genuinely useful info (discovered commands · gotchas · package relationships · testing approaches). Skip what's obvious from code or generic. Present each change as a diff + "why this helps."
5
Apply Updates
After approval, apply with Edit. Preserve the existing structure.

04

Tool ② /revise-claude-md

end-of-session slash command — record learnings one line at a time
COMMAND
/revise-claude-md
Fold this session's learnings into CLAUDE.md
allowed-tools:
Read · Edit · Glob

Reflects on the session to extract "what context would have helped future Claude sessions work more effectively." Because CLAUDE.md is part of the prompt, the key is to record one line per concept — brevity matters.

5-step procedure
1
Reflect
Identify what was missing: bash commands used/discovered, code-style patterns followed, testing approaches that worked, environment/config quirks, warnings & gotchas hit.
2
Find CLAUDE.md files
Decide where each addition belongs: CLAUDE.md (team-shared) vs .claude.local.md (personal · gitignored).
3
Draft additions
Format: <command or pattern> - <brief description>. Avoid verbose explanations, obvious info, and one-off fixes unlikely to recur.
4
Show proposed changes
Present each addition as ### Update + a one-line Why + a diff block.
5
Apply with approval
Ask whether to apply, and only edit the files the user approves.
# Run as a slash command (at the end of a session)
/revise-claude-md
05

Which to use when

claude-md-improver

When the code changed / periodically

  • After refactors or structural changes drift the docs from the code
  • When you want a score for "how's our CLAUDE.md doing?"
  • When you want to audit many CLAUDE.md files (monorepo) at once
  • To catch stale commands · broken paths · outdated architecture notes
/revise-claude-md

When a session ends / you just learned something

  • When the session surfaced new commands · gotchas · patterns
  • When something arises that "the next session should also know"
  • To quickly record context from what you just did, one line at a time
  • When you only need an incremental capture, not a full audit
06

Tips worth knowing

things the skill surfaces alongside its recommendations
# shortcut
During a session, press # to have Claude auto-incorporate learnings into CLAUDE.md.
.claude.local.md
Put personal settings not shared with the team here. Add it to .gitignore.
~/.claude/CLAUDE.md
Put user-wide defaults that apply across all projects.
Keep it concise
CLAUDE.md should be human-readable — dense is better than verbose.
Copy-paste commands
Every documented command should be copy-paste ready.
