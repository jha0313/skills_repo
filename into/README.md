# into

설명의 **뼈대**만 모은 스킬이다. PR, 논문, 저장소, 커뮤니티 글은 쉽게 읽히는 순서가 서로 다르다. into는 그 순서와 칸을 정하고, 말투와 그리기는 이미 쓰던 것에 맡긴다.

```text
말투        ELI5 · ASD-STE100 · 그냥           ← 내가 친다
뼈대        into PR · into 논문 · into 저장소   ← into
그리기      visualize · 문서 · 대화            ← 다른 스킬
```

## 외울 명령이 없다

자료를 가리키고 평소처럼 말하면 된다.

```text
ELI5로 이 PR 설명해줘 <링크>
codex github를 visualize해줘
ASD-STE100으로 이 RFC 설명해줘 <문서>
```

안 켜지면 둘 중 하나로 고친다.

1. `into로`를 붙여 부른다: `into로 이 파일 설명해줘`
2. 자기 `CLAUDE.md`나 `AGENTS.md`에 한 줄 적는다: `PR·저장소·논문·커뮤니티 글 같은 자료를 설명할 때는 into 스킬을 먼저 쓴다.`

## 이 조합으로 많이 쓴다

포맷이나 단계를 콕 집고 싶을 때.

| 하고 싶은 것 | 이렇게 친다 |
|---|---|
| PR을 빨리 이해한다 | `ELI5로, into PR <링크>` |
| 논문을 한 장으로 본다 | `/visualize into 논문 간단히 <파일>` |
| 처음 보는 저장소 | `/visualize into 저장소 간단히 <경로>` → `into 저장소 아주 자세히, src/auth만` |
| 설계 문서를 리뷰한다 | `ASD-STE100으로, into 설계 문서 자세히 <문서>` |
| 댓글 300개 | `ELI5로, into 커뮤니티 글 <링크>` |
| 영상을 볼지 정한다 | `into 영상 간단히 <링크나 자막>` |
| 남의 스킬을 깔기 전 | `into 스킬 아주 자세히 <폴더>` |
| 발표 자료 | `/visualize 슬라이드로, into 설계 문서 간단히 <문서>` |
| 새 분야를 배운다 | `/visualize into 커리큘럼 간단히 <분야>` |
| 방금 답이 어렵다 | `방금 답을 into 개념 간단히` |

단계는 셋이다. **간단히**(기본) · **자세히** · **아주 자세히**. 뒤 단계는 앞 단계를 넓히고 새 질문의 칸을 더한다.

## 확인한 것

2026-11-25, Claude Code를 부탁마다 새 대화로 띄워 쟀다. 스킬이 켜지고 맞는 포맷 파일을 여는 것까지 봤다.

| 설명문 | 켜져야 할 때 | 켜지면 안 될 때 |
|---|---|---|
| 2.0 초안("포맷 이야기가 없으면 쓰지 않는다") | 7번 중 1번 | 3번 중 3번 |
| 포맷을 visualize 안에 넣음 | 7번 중 2번 | 3번 중 3번 |
| 자료 종류로 다시 씀 | 30번 중 27번 | 8번 중 8번 |
| 지금 것('이 파일 뭐 하는 거야', '이 답 안 읽혀'를 더함) | 30번 중 30번 | 8번 중 8번 |

- 30번은 포맷 12개를 부르는 말 15가지 × 환경 2곳(스킬이 두세 개인 곳, 236개인 곳)이다. 말마다 환경당 한 번씩이라 작은 표본이다.
- 27번에서 빗나간 것: '파일 하나' 두 번(스킬이 안 켜짐), X 글 한 번(켜졌지만 포맷 파일까지 안 감).
- 27번과 30번은 똑같은 시험이 아니다. 말 두 가지(X 글 주소, 에이전트 답)를 바꿨고, 설명문에 더한 말은 시험한 말과 거의 같다.
- 안 잰 것: 한국어 밖의 부탁, 다른 모델, Codex, 긴 대화 중간. 이 시험에서는 웹을 열지 못하게 막았다.
- 결과물: 포맷 12개를 실제 자료로 한 번씩(공개 자료, 그 밖은 에이전트 답 하나) `간단히`까지 돌렸고 visualize로 5장을 그렸다. `자세히`와 `아주 자세히`는 칸 이름을 바꾸기 전에 몇 개만 돌렸다. **사람이 읽어 본 시험은 아직 없다.**
