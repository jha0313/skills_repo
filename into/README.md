# into

에이전트 아웃풋을 **내가 읽는 모양**으로 바꾼다. 무엇을 넣든 유형마다 정해진 틀이 나오고, 같은 자료를 모드만 바꿔 더 깊이 들어간다.

```text
into eli5 <PR·저장소·논문·영상·글·스킬>   ← 한눈에
into html                                ← 한 화면 그림
into interactive                         ← 눌러 보며
into doc                                 ← 제대로 읽기
into test · slides · shorts · video      ← 확인하고 남에게 설명하기
into domain-expert <분야>                ← 전문가 과정
```

설계와 이유, 잰 값은 [DESIGN.md](DESIGN.md).

## 유형마다 다른 틀, 순서는 같다

칸의 순서는 언제나 **한 줄 → 왜 → 그림 → 도는 순서 → 조심**이다. 이름과 모양은 유형에 맞춘다.

| 넣는 것 | 독자의 첫 질문 | 주 그림 |
|---|---|---|
| PR | 전에는, 지금은 | 전 → 후 두 줄 |
| 저장소 | 요청 하나가 어디를 지나나 | 지도 → 구역 한 바퀴 |
| 설계 문서 | 무엇을 정했나 | 길 + 이러면 → 이렇게 |
| 논문·개념 | 무엇보다 얼마나 | 결과 막대 + 왜 그랬나 |
| 영상 | 어디를 보면 되나 | 질문 → 답 시간줄 |
| X·스레드 | 무엇을 무슨 근거로 | 근거 종류가 붙은 줄 |
| 커뮤니티 글 | 왜 갈리나 | 입장 + 치른 대가 |
| 파일 하나 | 넣으면 무엇이 나오나 | 입구 → 출구 + 규칙 |
| 스킬 | 누가 판단하고 무엇이 정해졌나 | 레인 |
| 그 밖 | 무엇인가 | 오가는 것 |

틀은 [formats/](formats/)의 표다. 행을 고치면 스크립트가 그대로 따른다.

## 어떻게 만드나

```text
start(스크립트)  유형·크기·공개 여부를 정하고 원문에서 셀 것을 센다
읽기(에이전트)   model.json — 사실·간선·단계와 근거. 원문 하나에 한 번
check(스크립트)  근거 줄·숫자·이름·조건을 원문과 대조
쓰기(에이전트)   그 모드의 칸만
render(스크립트) 길이·배치·그림·근거 줄. FAIL이면 결과를 쓰지 않는다
```

`python3 scripts/into.py --help` · 시험 `python3 -I tests/run_tests.py` (Python 3.9+, 표준 라이브러리만)

## 내 틀로 바꾸기

- 한 번만: `into doc, 칸: 결론 / 근거 / 위험 / 다음 할 일`
- 계속: `formats/<유형>.md`의 행을 고치거나 새 파일을 더하고 `into.py formats --validate`.

## 설치

```bash
npx skills add jha0313/skills_repo --skill into
```

손으로 넣을 때는 폴더 전체를 스킬 경로에 복사한다. `python3`가 있어야 검사와 그림이 된다. 쇼츠·영상을 MP4로 만들려면 HTML→MP4 도구(예: hyperframes)가 따로 있어야 한다. 없으면 대본과 스토리보드까지다.

## 알아 둘 것

- 짧은 글은 다 담지 못한다. 끝의 `빠진 디테일`이 무엇을 뺐는지 말한다. 더 알고 싶으면 `into doc`.
- 스크립트는 근거 줄·숫자·이름이 원문에 있는지 본다. **뜻이 맞는지는 못 본다.** 중요한 결정은 원문으로 확인한다.
- STE는 ASD-STE100의 문장 규칙을 본뜬 것이다. 표준의 단어 사전과 대조하지 않는다.
- 읽기만 하면 안 것 같은 느낌만 남는다. `into test`로 먼저 예측해 본다.
- 로그인 벽·자막 없는 영상은 본문을 붙여 준다. 제목만으로 만들지 않는다.
- 비공개 원문이면 결과에 안내 줄이 붙는다. 공유 전에 이름과 경로를 확인한다.
