# 퀴즈

푸는 사람이 궁금한 것: 꼭 알아야 할 것이 무엇인가 · 나는 그것으로 판단할 수 있나 · 무엇을 다시 보나

| 단계 | 칸 | 채울 것 |
|---|---|---|
| 간단히 | 꼭 알아야 할 것 | 3~7개: 무엇 + 까닭 + 원문 자리. **문항보다 먼저 쓰고** 풀 때까지 숨긴다 |
| | 문항 6개쯤 | 꼭 알아야 할 것마다 하나. 가려내기 → 흐름 → 까닭 → 상황 판단, 끝은 `내 말로` |
| | 되먹임 | 답하면 바로: 맞음·틀림 → 까닭 → 고른 오답은 언제 참인가 → 원문 자리 |
| | 다시 | 틀린 것과 찍어 맞은 것만. 같은 사실, **다른 상황** |
| | 한 장 정리 | 꼭 알아야 할 것 전부, 틀린 것 표시, 내일과 일주일 뒤 풀 번호 |
| 자세히 | 조건 바꾸기 | 3문항. 앞 상황에서 조건 하나만. 답이 그대로인 것도 섞는다 |
| | 내 말로 더 | 2문항. 모범 답과 꼭 들어갈 것 2~3개 |
| 아주 자세히 | 긴 사례 | 상황 하나에서 판단 4~5번. 되먹임은 끝에 모아서 |

- 칸 → 문항: 한 줄 요약·배경 → 가려내기 · 동작 순서·방법 → 순서, 누가 하나 · 따라가기·전 → 후 → 예측 · 왜·핵심 결과 → 까닭만 다른 보기 · 기억할 것·한계 → 상황 판단, 오해 잡기
- 고르는 법: 모르면 다르게 행동하는 것 → 반대로 알기 쉬운 것 → 다른 것의 까닭. 이름과 숫자는 판단에 쓰일 때만.
- 문항: 전제를 다 적은 물음, 보기 셋, `확실/찍음`. 오답은 이웃 조건에서 참이거나 흔한 오해. 언제 참인지 못 쓰면 버린다.
- 내기 전 검사: **다 쓴 뒤** 원문 자리(`파일:줄 "그 줄의 글자"`)를 다시 열어 그 줄이 답을 정하나 · 다른 보기도 맞는 경우가 있나 · 가장 긴 보기로 풀리나(길이를 맞추고 정답 자리는 **쓰기 전에** 흩는다) · 앞 해설과 힌트가 답을 말하나 · **원문 없이 상식으로 풀리나**. 풀리면 경계를 묻는다(언제 아닌가, 이 자료만의 선택).
- 넘길 때: 화면은 visualize 같은 스킬이. 보기 섞기와 답하기 전 정답 숨기기를 부탁한다. 대화에서는 한 문항만 묻고 기다린다.
- 실수: 읽자마자 맞힌 점수를 "안다"고 쓰기. 6문항, 내일·일주일, `확실/찍음`은 잰 값이 아니라 설계다.
