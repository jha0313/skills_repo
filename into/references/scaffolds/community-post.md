# community-post 스캐폴드

**적용:** Reddit, Hacker News, Discourse 포럼, GitHub Discussions, 커뮤니티 게시판 글과 그 댓글. general의 다섯 칸 이름과 순서를 그대로 쓴다.

## 원문 읽기

- 원글과 댓글을 함께 읽는다. 댓글이 많으면 페이지에 표시된 정렬 기준으로 상위 20~30개와 원글 작성자의 답글을 읽는다.
- 읽은 범위를 `출처:`에 쓴다(예: "댓글 312개 중 상위 30개 + 작성자 답글 4개").
- 댓글 작성자 이름은 넣지 않는다. 입장을 구분할 때는 "댓글 A", "작성자"처럼 쓴다.
- 점수·추천 수는 페이지에 보인 그대로 쓴다. 추천이 많다는 것은 지지의 신호이지 정확성의 신호가 아니다. 추천 수가 보이지 않으면 정렬 순위나 답글 수로 대신하지 않는다. 그것은 '관심도'로 따로 적는다.
- 원글이 다른 글을 요약한 글(링크 게시판의 요약 등)이면 주어에 자료 층위를 밝힌다: "요약에 따르면", "원 기사에 따르면". 원 기사를 읽지 않았으면 `출처:`에 밝힌다.

## 변형 고르기

- **토론 글(기본):** 댓글이 많고 입장이 갈린다. 아래 표대로 쓴다.
- **본문 중심 글:** 원글 본문이 댓글보다 길거나 댓글이 5개 미만이다. HLD는 본문이 설명하는 구조(general 규칙), LLD는 본문의 핵심 경로 하나로 쓴다. 토론 지도는 Insights에 한 줄이나 LLD 끝 한 블록으로 줄인다. TL;DR 셋째 줄은 "가장 중요한 제약 + 댓글 합의 여부"로 바꾸고, 노드 한도는 general을 따른다. **도구 사용기**면 HLD는 글쓴이의 일 · 고른 것 · 이유로 그리고, LLD는 원문이 순서를 밝힌 대표 사례 하나로 쓴다. 평소 습관("주로")과 가정한 선택("예산이 적다면")은 다른 상황이다. 날짜가 있는 사용기는 첫 요약과 "현재·아직"이 나오는 자리에 기준 시점을 쓴다.

## 섹션 순서

| # | 섹션 | 쓸 것 | 길이 한도 |
|---|---|---|---|
| 1 | TL;DR | 원글의 질문·주장 / 커뮤니티의 결론(없으면 "합의 없음") / 가장 추천받은 답 한 줄(추천 수가 보이지 않으면 `확인 불가`) | 3줄 |
| 2 | 왜 중요한가 | 이 토론이 다루는 문제, 누구에게 해당하나 | 글머리 3개 |
| 3 | High-level design | **토론 지도**: 원글 → 입장 2~4개(지지·반대·대안·추가 질문). 화살표 라벨 = 근거 종류 | 노드 6개 |
| 4 | Low-level design | 입장마다 근거(측정·경험담·링크·코드). 재현 절차·명령·설정값이 있으면 원문 그대로 | 입장당 3줄 |
| 5 | Insights | 합의된 것 / 엇갈리는 것 / 일화뿐인 주장 / 작성자가 마지막에 택한 것(있을 때) | 글머리 4개 |

- **엇갈리는 것:** 대상·작업·조건·평가 기준이 같은 두 주장만 엇갈림으로 쓴다(general "엇갈림·충돌"). "at least", "~수준은 아니지만" 같은 한정어를 줄이지 않는다.
- **없다는 판정:** "반대 의견 없음"은 "읽은 범위에서 직접 반박한 댓글 없음"으로 쓰고, 다른 조건에서 다른 결과를 말한 간접 반례를 찾아 함께 적는다. 작성자 이름을 지운 사본이면 작성자 답글 여부는 `확인 불가`로 쓴다(fact-card.md 4절).

## 다이어그램 규칙

- 토론 지도의 노드 라벨은 입장을 한 구절로 쓴다("캐시를 끄면 해결됨"). 사람 이름을 쓰지 않는다.
- 입장 노드 이름을 묶은 댓글 하나하나와 대조한다. 한 댓글이라도 맞지 않으면 노드를 나누거나 이름을 넓힌다(예: "대개 A, 가끔 B"인 댓글은 "하나만 쓴다" 입장에 넣지 않는다).

## general에서 바꾼 점과 이유

- HLD를 토론 지도로 바꿨다 — 커뮤니티 글의 구조는 입장들의 관계다.
- 본문 중심 글은 본문 구조를 그린다 — 긴 본문에 짧은 댓글 몇 개가 달린 글을 토론 지도로 그리면 본문의 핵심이 빠진다.
- LLD를 입장별 근거로 바꿨다 — 같은 결론도 측정으로 뒷받침한 것과 경험담은 무게가 다르다.
- TL;DR에 "합의 없음"을 허용했다 — 결론이 없는 토론에 결론을 만들어 붙이면 사실을 바꾼 것이다.
- 읽은 범위를 밝힌다 — 일부 댓글만 읽고 '커뮤니티 의견'이라고 쓰면 대표성을 과장한다.
- 작성자 이름을 넣지 않는다 — 이해에 필요 없고 개인 정보다.
