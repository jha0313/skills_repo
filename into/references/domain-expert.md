# domain-expert — "이 과정을 통과하면 이 분야의 전문가다"

커리큘럼 한 벌을 만든다: 비전 하나 → 전략 하나 → 목표 하나 → 지표 → 섹션마다 결과물 하나. 레슨은 다른 모드로 만든다. **화면의 글은 짧게.** 조건은 채점표와 졸업 조건에서 한 번만 말한다.

```text
into-out/<slug>-domain-expert/        index.html(허브, build_domain.py가 만든다) · curriculum.json(원본) · research/ · lessons/<섹션 id>-<모드>.*
into-out/<slug>-domain-expert-author/ 시험 설계표·정답·고침 기록. 학습자에게 주지 않는다
```

입력은 분야 이름·저장소·이미 만든 into 결과. 묻지 않고 시작하고 가정은 `learner`에 적는다. `커리큘럼만`이면 레슨 대신 만드는 명령(`cmd`)을 넣고 진단까지만 만든다. 이 모드만 다른 모드를 스스로 부른다.

## 1. 순서

1. **조사** — [domain.md](domain.md). 장부가 끝나기 전에 커리큘럼을 쓰지 않는다.
2. **전문가가 하는 일 5~8개** — 장부에서, 출처 id와 함께. 채용 공고의 낱말이 아니라 행동("장애가 나면 어느 층인지 5분 안에 좁힌다").
3. **비전 → 전략 → 목표 → 지표**(2절).
4. **섹션 8~14개** — 일에서 거꾸로. 섹션 = 질문 하나 + 결과물 하나. `uses`에 앞 결과물의 어느 행을 가져와(`take`) 무엇을 하는지(`do`). 가져갈 행은 앞 채점표가 반드시 만들게 한다.
5. **시험 설계표**를 author 폴더에. 섹션마다 할 수 있어야 하는 것 한 줄, 진단·게이트·졸업이 `쓰는 사실`. 같은 사실이 두 시험에 나오면 바꾼다.
6. **레슨 형식을 고르고**(3절) 만든다. 같은 장부·같은 model을 쓴다.
7. `python3 -I S/scripts/build_domain.py <과정 폴더>`가 FAIL 0일 때까지.
8. **처음 온 사람으로 걷는다** — 허브 → 진단 → 첫 섹션 → 결과물 → 게이트. 레슨만 보고 결과물을 만들 수 있나?

## 2. 비전 · 전략 · 목표 · 지표

| 칸 | 길이 | 규칙 | ✗ → ○ |
|---|---|---|---|
| learner | 130 | 누구, 주 몇 시간, 다루지 않는 것 | |
| vision | 95 | 전문가가 **하는 일**. 남이 볼 수 있는 행동 + 조건, 한 문장 | "X를 깊이 이해한다" → "처음 보는 X 장애에서 어느 층이 막았는지 근거 줄을 대고 고칠 안을 동료가 채택하게 한다" |
| strategy | 180 | 길 하나와 고른 이유 | "열심히 공부" → "지도를 외워 그리고, 예측 → 확인을 되풀이한 뒤, 실제 사례를 고친다" |
| goal | 180 | 끝났는지 판정할 조건 | "전문가 수준" → "졸업 17/20, 결과물 12개, 졸업 과제를 다른 사람이 채점표로 통과" |
| kpis 3~6 | | 재는 법 · 시작 · 목표 · 올리는 섹션 | "읽은 문서 수" → "처음 보는 상황 10개에서 다음 동작을 맞힌 수" |

- 지표는 비전의 행동을 잰다. `manual`이 하나 이상, 실제 일에서. 시작과 끝은 **같은 답안이면 같은 점수**여야 한다(같은 표본 수·난도·채점법). 실제와 모의를 섞어 더하지 않는다.
- 지표마다 세 사람을 대입한다: 아무것도 안 한 사람, 틀린 판단을 고집한 사람, 무엇에나 같은 답을 내는 사람. 넘으면 바꾼다.
- `how`에 예시 표본 하나를 끝까지 채운다. 분모가 0이거나 동률·부호가 바뀌는 입력에서 어떻게 세는지 적는다. 목표 값은 근거가 있거나 `(제안)`.
- `proof`: 비전의 동사마다 졸업 증거 하나(`capstone:3` · `M1:2` · `K4`, 앞의 둘은 `must`). **그 능력만 빠진 제출물을 만들어 졸업까지 채점한다.** 통과하면 필수를 고친다.
- `source`: exam · gates · deliverables · manual. 작을수록 좋으면 `dir:"down"`.
- 섹션도 같은 칸을 한 문장씩. 섹션 비전을 이어 읽으면 전체 비전이 된다.

## 3. 단계와 형식

| 단계 | 끝나면 | 결과물 | 형식 |
|---|---|---|---|
| Easy | 지도를 그리고 말을 안다 | 지도·용어 카드·2분 설명 | eli5 · shorts · html · ste |
| Medium | 다음 일을 맞힌다 | 예측표·절차서·점검표 | interactive · html · ste · video |
| Hard | 왜인지 근거로 말하고 실패를 해부한다 | 사례 해부·추적·비교 | doc · interactive · source |
| 심화 | 판단하고, 만들고, 가르친다 | 제안·적용 기록·발표 | slides · doc · source · video |

막히는 이유로 고른다(`why`에 한 문장, 60자): 감이 없다 → eli5·shorts / 말이 헷갈린다 → ste / 무엇이 이어지나 → html / 조건에 따라 다르다 → interactive / 긴 흐름 → video / 근거·예외 → doc / 1차 자료 → source / 남에게 설명 → slides / 안다고 느낀다 → test

- 섹션마다 레슨 2~4개, 형식 2가지 이상. 뒤 레슨은 앞에 없던 질문에 답한다. 레슨은 그 결과물을 만들 재료를 다 준다.
- `source` 레슨은 `url` + 읽을 절 + 들고 갈 질문. 로그인이 필요한 원문은 쓰지 않는다. 저장소 코드는 `lessons/<id>-source.md`에 40줄까지 그대로 옮긴다.
- 쇼츠·영상은 볼 때 할 일을 `why`에. 대본 레슨에는 제작 지시를 두지 않는다.
- 있는 into 결과는 다시 만들지 않는다. 있는 퀴즈를 게이트로 쓰려면 섹션 질문을 묻고, 답이 레슨에 있고, 5~8문항, 절반 이상이 적용이어야 한다.

## 4. 시험과 결과물

| 시험 | 문항 | 쓰임 |
|---|---|---|
| 진단 | 섹션마다 1~2, 모두 12~24 | 시작값. 막지 않는다 |
| 게이트 | 섹션마다 5~8, 기준 70% 이상 | 다음으로 가도 되나 |
| 졸업 | 진단과 같은 배분·수·난도, 다른 상황 | 앞뒤를 잰다. 첫 점수만 |

- 문항은 [test.md](test.md)를 따르되 `section`은 섹션 id로 시작한다. 절반 이상이 적용(새로 내려야 하는 결정). 레슨에서 해부한 사건의 결말은 회상이다.
- 정답은 원문이 **말한 것까지만**. "본문에 없다"를 "없었다"로, 관찰 차이를 "효과 없음"으로 쓰지 않는다. 선택형은 **정답이 뒤집히는 전제 하나**, 서술형은 **다른 맞는 답 하나**로 거꾸로 검수한다.
- 해설·레슨·게이트를 모두 펼친 채 졸업 문제를 푼다. 베껴서 풀리면 바꾼다. 졸업에만 쓰는 사례는 `hold:true`.
- 판단이 일인 섹션의 게이트는 남의 답을 채점표로 채점하게 한다.
- 퀴즈는 `assets/test.html`의 최신 동작 코드로. 졸업 파일만 `QUIZ`에 `exam:true`, 새 문제면 `QUIZ.rev`·`final.rev`를 함께 올린다.

**결과물은 섹션마다 하나.** `what · form · steps(3~7) · rubric(3~7, 졸업은 9까지) · pass · answer(꼭 들어갈 것·흔히 빠지는 것·근거 위치)`

- 남이 봐도 같은 답이 나오는 채점표("잘 설명했다" ✗ → "라벨 없는 화살표 0개" ○). 개수·형식만으로 통과하지 못하게 원문과 대조하는 항목을 두고 `must`.
- 필수 능력마다 그 능력만 틀린 제출물을 채점해 본다. 판정 순서가 있으면 두 조건이 동시에 참인 입력도 넣어 본다(사실·안전 정정은 성과 판정과 따로).
- **정직한 끝을 통과시킨다:** 하지 않기로 함, 일찍 멈춤, 0건, 계산 불가, 반박받아 거둠. 가장 작은 조건(최소 표본, 권한·기록 없음)에서도 만들어 본다. 없는 사람을 위한 예제 자료를 준다.
- 빈 양식은 하나: 레슨 예시·단계·채점표·모범 기준이 같은 칸 이름을 쓴다. 예시대로 채우면 통과해야 한다.
- 졸업 과제는 앞 결과물 셋 이상을 다시 쓰고 **다른 사람이나 실제 사용**으로 확인한다. 실제 시스템을 건드리면 안전한 범위를 `form`에.

- 섹션 id는 영문자 + 번호이고 출처 장부 id와 앞 글자가 겹치지 않게 한다(장부가 E·H를 쓰면 `EZ1`·`HD1`).
- 단계 이름은 `Easy` · `Medium` · `Hard` · `심화` 넷. 문장에는 마크다운을 쓰지 않고 `` `코드` ``와 `**굵게**`만 쓴다.
- 시간은 추정이다. 레슨 분 + 결과물 + 게이트를 더해 적는다.
- 저장소 도메인은 `cases` 대신 코드 안의 실패·예외를 섹션에 쓰고 `cases`를 빈 목록으로 둔다. `sources`는 지도·구역·핵심 파일이다.
- 저장소 도메인의 기본 배치: Easy = 지도 + 용어, Medium = 핵심 경로 구역, Hard = 나머지 구역과 실패·경계, 심화 = 구역을 가로지르는 추적 · 바꾸는 설계 · 가르치기.

## 6. 정직하게

- 전문가 = 목표를 통과한 사람. `honesty`에 약속하지 않는 것을 적는다. 모르는 곳·약한 근거(C·D)·엇갈리는 값은 `gaps`에 남긴다.
- 사례의 제목·이유·수치마다 **누가 말했는지와 그 행의 등급**을 남긴다. 확인되지 않은 원인은 "미확인". 같은 출처의 사례 여럿은 증거 하나. 성공·실패 수를 밝힌다.
- 비공개가 섞이면 `notice`를 달고, 과정 폴더 옆 `<과정 폴더 이름>.deny.txt`(저장소·사람·내부 경로)로 빌드한다. 검토자에게는 결과물만 보낸다.

끝내기 전: FAIL 0 · WARN마다 남긴 이유를 안다 · 브라우저에서 진단 → 섹션 → 게이트 → 졸업을 눌러 점수가 들어간다 · 콘솔 오류 0 · 가로 스크롤 0.
