# doc 모드

**목표:** 남에게 넘기거나 나중에 다시 볼 수 있는 이해 문서. 대화 출력보다 자세하지만 같은 칸, 같은 순서다.

**출력:** `into-out/<slug>-doc.md` (사용자가 경로를 주면 그곳).

## 문서 구조

```markdown
# <주제> — 이해 문서

> 원문: <링크·경로> · 유형: <type> · 스캐폴드: <이름>

## 1. TL;DR
## 2. 왜 중요한가
## 3. High-level design
<Mermaid 다이어그램>
<다이어그램을 글로 읽는 2~4줄>
## 4. Low-level design
<Mermaid 다이어그램 또는 표>
| 식별자 | 위치 | 하는 일 |
## 5. Insights
## 빠진 디테일 · 불확실
## 출처
```

칸마다 끝에 `근거:` 줄로 위치를 단다. 사용자 스캐폴드면 1~5 대신 그 칸 이름과 순서를 쓴다. 비공개 원문이면(SKILL.md 4절) 안내 한 줄을 `# 제목`보다 먼저, 파일 첫 줄에 둔다. 대화 모드(eli5·ste)에는 이 줄을 달지 않는다.

## 길이 한도

유형과 상관없이 이 숫자를 쓴다: TL;DR 3줄, 왜 중요한가 글머리 6개, HLD 노드 9개(그림마다), LLD 메시지 16개(표면 16행), Insights 글머리 7개 + 유형이 요구하는 표 1개(대안 비교 등). 문서 전체 200줄 이하. LLD 메시지 수에는 `alt`·`else`·`opt`·`loop`·`break` 안의 메시지도 넣고, `Note`는 넣지 않는다. 짧은 원문이면 general "짧은 원문"의 상한과 구성(그림 하나 + 표 하나 + Insights)을 먼저 따른다.

## 다이어그램 (Mermaid)

- HLD는 `flowchart LR`. 한 대상의 상태 변화가 핵심이면 `stateDiagram-v2`.
- LLD는 실행 순서가 있으면 `sequenceDiagram`. 유형의 LLD가 실행 순서가 아니면(근거 점검표, 입장별 근거, 설정 키 표, 규칙 목록) 시퀀스를 만들지 않고 Markdown 표로 쓴다.
- **flowchart 라벨:** 한글이나 특수 문자(괄호·콜론·슬래시)가 든 라벨은 따옴표로 감싼다: `A["작업 루프"]`, `A -->|"도구 호출 요청"| B`.
- **sequenceDiagram 글자:** participant 별칭·메시지·`Note`에는 따옴표를 쓰지 않는다(따옴표가 그대로 보인다). `;`와 `#`도 쓰지 않는다. `;`는 문장 끝으로 읽혀 렌더가 깨진다(`TL;DR` → `TLDR`). 글자를 빼거나 바꿀 때도 `!`·`&&`·`||`·비교 연산자는 남긴다. 못 쓰면 말로 쓴다(`!x` → `x가 아니면`). 빠지면 조건의 뜻이 뒤집힌다.
- 모든 간선에 라벨을 단다. 핵심 경로는 `==>`로 굵게 한다.
- **sequenceDiagram의 흐름:**
  - 메시지 수신자는 원문이 말한 실제 수신자로 쓴다.
  - 반복은 `loop` 블록으로 쓴다. 반복 중에 일어나는 중단·취소는 그 `loop` 안의 분기로 둔다.
  - 루프 안에서 흐름이 끝나는 경로(조기 return·즉시 중단·거절)는 그 `loop` 안의 `break` 블록으로 그린다. 그 뒤에 반복을 잇지 않는다.
  - 정상 종료·취소·실패는 서로 다른 `alt`/`else` 분기로 쓴다. 같은 `alt`의 분기는 같은 층위끼리 둔다(응답 형식끼리, 결과 종류끼리).
  - 흐름이 끝나는 분기(return·`?`·거절)는 메시지 글자("오류면 반환")로 쓰지 않고 `alt`/`else`나 `break`로 그린다. 남은 정상 흐름은 `else` 안에 둔다. 분기 뒤에 정상 흐름을 이어 붙이지 않는다.
  - 한쪽만 있는 조건("값이 없을 때만", "통과하면")은 `opt`로 쓴다. 원문의 "A 또는 B" 대안은 순서로 그리지 않고 `alt`/`else`로 쓴다.
  - 호출 자체를 건너뛰는 조건(한도 초과·캐시 적중·skip)은 그 호출 **앞**의 `alt`/`opt`로 그린다. 조건 분기를 호출 뒤 `Note`로 쓰지 않는다.
  - 발췌가 `중략`으로 자른 구간을 건너는 순서·종료는 그리지 않는다(general 대화 LLD 규칙). 순서를 모르면 `Note`에 `앞뒤 순서는 발췌에서 빠짐`을 쓰고, 종료를 확정하는 글로 읽기 문장을 쓰지 않는다.
  - `alt`/`else`는 실제 실행 분기에만 쓴다. "확인된 것 / 확인되지 않은 것" 같은 확실성 구분에 쓰지 않는다. 분기나 메시지 자체가 추정이면 `alt` 조건이나 메시지 끝에 `(추정)`을 단다.
  - 다음 동작이 원문에 없으면 `Note`에 `이후 동작은 원문에 없음`을 쓰고 흐름을 잇지 않는다.
- Mermaid를 렌더하지 못하는 독자를 위해 다이어그램 아래에 글로 읽는 설명을 둔다. 글로 읽기는 다이어그램의 메시지 순서를 그대로 따라 번호를 붙인다. 실패 경로가 가리키는 단계 번호를 이 번호와 대조한다.

## 문장

- 문서는 남이 읽고 행동하는 글이다. 문장에는 [ste.md](ste.md)의 규칙 6개를 기본으로 적용한다. 사용자가 쉬운 말투를 원하면 [eli5.md](eli5.md)의 용어 규칙을 쓴다.
- 앞선 eli5에서 `빠진 디테일`로 적힌 항목은 doc에서 되살린다. 되살릴 수 없으면 `빠진 디테일 · 불확실` 절에 남긴다.

## 점검

- [ ] Mermaid 블록을 렌더해 문법 오류가 없음을 확인했다. 렌더 도구가 없으면 위 글자 규칙을 블록마다 손으로 점검하고 `출처` 절에 "다이어그램 렌더 미확인"이라고 적었다.
- [ ] 시퀀스의 반복·종료·실패 분기가 원문의 제어 흐름과 같다. 끝나는 분기 뒤에 정상 흐름이 이어지지 않는다.
- [ ] 글로 읽기의 순서와 단계 번호가 다이어그램과 같다.
- [ ] 식별자 표의 위치가 실제 원문 위치다.
- [ ] `빠진 디테일 · 불확실` 절과 `출처` 절이 있다.
