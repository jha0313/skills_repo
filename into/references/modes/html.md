# html 모드 (= visualize)

**목표:** 한 화면에서 전체 구조를 본다. 아주 단순하고 추상화된 그림 한 장이다. 예쁘게 만드는 것이 아니라 한 장에 모으는 것이 목표다. 세부는 doc 모드에 맡긴다.

**출력:** `into-out/<slug>-html.html`. [assets/page.html](../../assets/page.html)을 복사해 `{{...}}` 자리를 채운다. 한 화면에 맞추려고 레이아웃 CSS(열 비율·여백·글자 크기)를 고쳐도 된다. 색 변수, 링크 색(`a`), `.src`·`.fail`·`.notice` 규칙, 외부 요청 0개는 유지한다. 비공개 원문이면 맨 위 `notice` 자리에 SKILL.md 4절의 한 줄을 쓰고, 아니면 그 줄을 지운다.

## 화면 배치 (스캐폴드 순서대로)

| 위치 | 칸 | 한도 |
|---|---|---|
| 맨 위 | 1. TL;DR | 큰 글씨 한 줄 + 보조 1~2줄 |
| TL;DR 아래 | 2. 왜 중요한가 | 한 줄 |
| 가운데 왼쪽(넓게) | 3. High-level design | 인라인 SVG, 노드 7개 |
| 가운데 오른쪽 | 4. Low-level design | 핵심 경로 번호 단계 6개(`✗` 줄은 세지 않는다). pr 변경 목록 형식이면 pr.md "LLD 자리가 작은 모드" |
| 아래 | 5. Insights | 카드 3개 |
| 맨 아래 | `빠진 디테일:` · `출처:` | 각 한 줄 |

- 칸마다 근거 위치를 `<small class="src">`에 단다(템플릿 자리). 근거가 길어 한 화면을 넘으면 단계별 근거를 칸 끝 한 줄에 번호로 모은다(`① path:n · ② path:n`).
- 유형 스캐폴드가 칸 형식을 정하면 그것을 따른다(SKILL.md 2절). 예: LLD가 근거 점검표·입장별 근거·키/값 표면 3열 이하의 작은 표로 쓰고, video 스캐폴드면 노드·단계마다 `[mm:ss]`를 단다.
- **전/후 그림**(pr·design-doc): 후 그림 하나에 바뀐 노드·화살표를 `*`로 표시하고, 그림 아래에 `전:` 캡션 한 줄을 둔다.
- 사용자 스캐폴드면 칸 이름과 순서를 그 스캐폴드에 맞추고 같은 위→아래 흐름을 쓴다.

## 규칙

- **단일 HTML, 외부 요청 0개.** CSS·JS는 인라인, 다이어그램은 인라인 SVG. CDN·웹폰트·원격 이미지를 쓰지 않는다. 출처 URL은 `<a href>` 링크로 걸어도 된다(누르기 전에는 요청이 없다). `src`·`url()`·`<link>`에는 원격 주소를 쓰지 않는다.
- **한 화면:** 1280×800 창에서 세로 스크롤 없이 보이게 한다. 좁은 화면에서는 세로로 쌓이고 페이지에 가로 스크롤이 생기지 않게 한다. 넘치면 단계를 합치거나 문장을 줄인다. 식별자는 앞의 모듈 경로를 줄여도 되지만 끝 이름은 원문 그대로 쓴다.
- **짧은 문구도 사실이다.** 제목(h1)·보조 줄·카드·라벨·`aria-label`은 원문의 확실성 수준과 조건을 유지한다(SKILL.md 3절, fact-card.md 2절). 예: 원문 "may lack evidence" → "근거가 없을 수 있다"(✗ "확인할 수 없다").
- **추상화:** 박스 라벨은 2~4단어. 설명 문장은 짧게, 화면 전체를 1분 안에 읽을 분량으로. 숫자와 식별자는 줄여도 원문 그대로 쓴다.
- **동작을 그린다:** 화살표마다 무엇이 오가는지 라벨. 핵심 경로만 강조색 한 가지로 표시한다.
- **장식 금지:** 그라데이션, 아이콘, 의미 없는 색, 애니메이션을 넣지 않는다. 흥미롭지만 상관없는 장식은 이해를 방해한다.
- **라이트·다크:** 템플릿의 CSS 변수를 쓴다. SVG 색도 변수(`var(--...)`)나 클래스로 준다.

## SVG 다이어그램

- `viewBox`를 쓰고 `width`는 100%. 글자는 **화면에 그려진 크기로** 14px 이상이다: `font-size × SVG 실제 폭 ÷ viewBox 폭`. 열 비율이나 viewBox 폭을 바꾸면 다시 잰다. viewBox 폭은 템플릿(720) 안팎으로 둔다. 좁은 화면에서는 템플릿의 `.fig`가 그림 안에서만 가로로 밀리게 한다.
- 박스 폭을 라벨 글자 수에 맞춰 글자가 박스 밖으로 나가지 않게 한다. 한글 한 글자는 대략 글자 크기만큼 폭을 차지한다.
- 화살표는 템플릿의 `marker`를 쓴다. 라벨은 화살표 중간 위쪽에 두고 다른 선과 겹치지 않게 한다. 대각선 화살표의 라벨은 선에서 떨어뜨리거나 라벨 뒤에 배경 `rect`(`class="lbl-bg"`)를 깐다. 양방향 화살표 하나에 라벨을 달지 않고 두 화살표로 나눈다.
- 노드가 7개를 넘으면 묶는다. 묶은 내용은 `빠진 디테일:`에 쓴다.
- 본문에서 `(추정)`인 간선은 `class="edge guess"`(점선)로 그리거나 라벨에 `(추정)`을 단다.
- `<svg role="img" aria-label="...">`에 다이어그램을 한 줄로 설명한다. LLD가 확대한 구간의 순서와 주체는 LLD 번호 목록과 같게 쓴다. `(추정)`·"가능" 같은 표시와 한정어를 그대로 둔다.

## 점검

- [ ] 파일 안에 `http://`, `https://`로 시작하는 `src`·`url()`·`<link>`가 없다(출처 `<a href>`는 예외).
- [ ] SVG 글자가 박스를 넘거나 선·다른 글자와 겹치지 않는다. 그려진 글자 크기를 쟀다(14px 이상).
- [ ] 다섯 칸이 모두 있고 순서가 스캐폴드와 같다. 칸마다 근거 위치가 있다.
- [ ] h1·보조 줄·카드·라벨·`aria-label`을 사실 카드의 조건·한정어·상태 열과 대조했다(fact-card.md 2절). `(추정)` 간선이 표시되어 있다. `aria-label`의 "그다음 …"에는 앞 판정의 진입 조건("허용되면")이 있다.
- [ ] 간선마다 발신자 → 수신자, 라벨, 주체를 원문과 대조했다(general 다이어그램 규칙). LLD 단계가 칸 제목에 적은 경로 안에 있다.
- [ ] 라이트·다크 두 테마에서 출처 링크와 글자가 보인다.
