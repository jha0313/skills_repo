# 판단 — 스크립트가 못 보는 것

작업 지시가 적은 절만 읽는다(큰 원문 1절, interactive·test 1·2절). 그 밖에는 `check`가 WARN을 낸 사실에 3–5절.

## 1. 카드 반박 (모드를 쓰기 전)

`model.json`의 `key` 사실마다 거짓이 되는 경우를 원문에서 찾는다. 하위 에이전트나 다른 모델이 있으면 사실과 원문 위치만 주고 시킨다(내 결론은 주지 않는다). 돌아온 지적은 원문을 열어 맞는 것만 반영한다.

1. **다른 입구** — 이 조건 없이 같은 결과로 가는 길이 있나. "필수·~만"을 쓰기 전에 호출자를 모두 찾는다.
2. **앞선 끝** — 여기 닿기 전에 끝내는 검사·캐시가 있나.
3. **뒤의 분기** — 이 판정 뒤에 결과를 다시 바꾸는 곳이 있나. `허용`이 곧 `실행`은 아니다.
4. **종류** — 모드·플랫폼·대상이 다르면 어떤가. 기본값은 어느 층의 기본값인가.
5. **단위와 경계** — 시도마다인가 전체인가, 이상인가 초과인가, 무엇부터 재나.
6. **주체와 방향** — 누가 하나. 돌려주는 값인가, 저장해 두고 나중에 읽나.
7. **때** — 처음과 재시도가 같은가. 기록한 때와 일어난 때가 같은가.
8. **문장 폭** — 모두·항상·~만을 지우거나 좁혀야 하나.

글·논문·댓글이면 셋만: 주체가 원문에 있나 / 두 문장을 이어 새 주장을 만들었나 / 한정어가 어디에 붙나.

## 2. interactive와 test는 쓴 뒤에 한 번 더

- interactive: 펼친 길마다 ① 고른 것들이 한 번에 참일 수 있나 ② 다음 단계가 앞 단계가 실제로 부르는 것인가 ③ 끝 문구가 이 길에서 참인가. 갈림길 **앞**의 글은 모든 갈래에서 참이어야 한다.
- test: 문항마다 전제를 만족하면서 다른 보기가 맞게 되는 입력을 하나 찾는다. 있으면 고친다.

## 3. 뜻이 바뀌는 줄임 (하지 않는다)

| 원문 | 바뀐 것 |
|---|---|
| 할 수 있다 · can | 한다 |
| 하지 않아도 된다 | 하지 마라 |
| 기본값이 꺼짐 | 기능이 없다 |
| 아직 실수한다 | 줄지 않았다 |
| 재는 법을 밝히지 않았다 | 잴 수 없다 |
| 다섯 개 이상 | 다섯 개 |
| 조건이 맞으면 | 언제나 |
| 권고(SHOULD) | 의무 |
| X 덕분에 가능 | X가 없으면 불가능 |
| 자동으로 허용하지 않는다 | 막는다 |
| A이면 B로 간다 | A여야 B로 간다 |
| 시도마다 최대 3번 | 최대 3번 |
| 저장하고 나중에 읽는다 | 돌려준다 |

## 4. "없다"도 주장이다

원문 전체를 핵심어와 동의어로 찾은 뒤에만 쓴다. 표현이 없는 것, 근거가 없는 것, 재는 법이 없는 것은 다르다. 읽은 범위가 일부면 "읽은 범위에서"를 붙인다.

## 5. 추정

원문 두 문장을 이어 만든 판단은 `추정`. 원문 밖 자료로 채우면 `보충`과 그 근거. 기억만으로 채우지 않는다. 원문이 원인을 말하지 않으면 비유에서도 원인을 붙이지 않는다.
