# 코드 읽기 — 저장소 · PR · 스킬 · 코드 파일

실행하지 않고 읽기만 한다. 센 값(커밋·파일 수·줄 번호·변경 규모)은 `pack.md`에 있다. 다시 세지 않는다.

## 읽는 순서

1. **고정** — `pack.md`의 커밋과 범위를 그대로 쓴다.
2. **구역** (저장소 지도) — 최상위 폴더·패키지 **전부**를 5~9개 책임으로 나눈다. 이름은 폴더가 아니라 하는 일. 남는 것은 `구역 밖`. 구역마다 읽기 등급: `읽음`(본문과 호출 위치) · `훑음`(머리와 공개 이름) · `목록만`(이름과 크기). 훑음에는 동작을, 목록만에는 책임도 쓰지 않는다.
3. **길 하나** — 요청 하나가 들어와 결과가 나갈 때까지. 사용자가 말한 것 → 기본값이 가리키는 것 순서로 고른다.
4. **따라간다** — 입구 → 호출 위치 → 끝(저장·응답·화면). 실패는 만든 곳 → 잡는 곳 → 보이는 곳.
5. **멈춘다** — 길의 간선마다 호출 위치가 있고, 실패가 어디서 끝나는지 알면 멈춘다.

PR이면: 바뀐 **동작**만 고른다(이름 바꾸기·포맷·생성물은 수만). 호출자·이전 동작·이유가 diff 밖이면 병합 커밋의 그 파일을 읽어 `보충`으로 쓴다.

## 틀리기 쉬운 것

- **정의 ≠ 호출.** "A가 B를 부른다"는 호출 위치로. 테스트가 아닌 호출이 없으면 길에서 뺀다.
- **타입 기본값 ≠ 실제 기본값.** 설정 합치기 → 진입점이 덮는 값 → 기능 플래그 → 서버가 주는 값까지 본다. 어느 층인지 쓴다.
- **판정 ≠ 실행.** `허용`을 돌려준 뒤 다시 막는 분기를 끝까지 본다.
- **시도 ≠ 성공.** 실패해도 계속하는 호출은 "시도한다". 기록된 상태와 실제 상태는 다르다.
- **병렬 ≠ 순서.** 뒤가 앞을 기다리는지 본다.
- **한 경로 ≠ 모든 경로.** 종류(주 세션·하위·백그라운드, 처음·재시도)마다 다른지 본다.
- **없음 · 시간 초과 · 취소 · 거절 · 오류**는 서로 다르다.
- **동작은 코드, 의도는 주석·문서.** 다르면 코드를 따르고 다르다는 것을 catch에 쓴다.
- **숫자 상수**는 단위·경계(`>`/`>=`)·무엇부터 재는지까지.
- 인용한 줄의 바깥 `if`·가드·조기 반환을 거슬러 올라가 `if`(조건)에 적는다.

## 스킬이면

- 나누는 선은 하나다: **정해진 동작(스크립트·템플릿)** 과 **판단(에이전트)**. 단계마다 어느 쪽인지, 무엇을 넘기는지 본다.
- 발동(`description`) → 먼저 읽는 파일 → 조건부로 읽는 파일 → 스크립트 → 결과. 실제 로드되는 글자 수는 `pack.md`에 있다.
- 설계 결정은 원문(본문·README·변경 기록·주석)이 이유를 말할 때만 이유로 쓴다. 말하지 않으면 `추정`.
