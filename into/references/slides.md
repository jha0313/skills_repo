# slides — 장마다 그림 하나가 말한다

`slides.json`을 쓰고 `render`하면 스크립트가 껍데기(assets/slides.html)에 넣고 장 수·글 양·그림 수·다음 질문·노트·출처를 검사한다. 장의 순서와 제목에 담을 것은 `formats/<유형>.md`의 `## slides` 표.

```json
{"slides":[
 {"slot":"cover","title":"주제","say":"한 줄","viz":"motion-inline","data":{…},"alt":"그림 한 줄 설명","next":"다음 장이 답할 질문","notes":"말할 것 2~4문장","f":["f1"]},
 {"slot":"pic","title":"주장하는 문장","viz":"flow","data":{…},"alt":"…","next":"…","notes":"…","f":["f3"]},
 {"slot":"close","title":"한 문장 정리","viz":"predict","data":{…},"alt":"확인 질문","notes":"답과 이유"}]}
```

데이터 모양은 `assets/slides.html`의 예시 장(주석)에서 쓸 부품 것만 본다.

## 그림 고르기 — 사실의 모양을 먼저 본다

| 사실의 모양 | 부품 | 조심할 것 |
|---|---|---|
| 양을 견준다 | `chart` hbar·bar·stack·cells, 넓이면 `map` | 축은 0부터. 분모·시점·표본을 `axis`에 |
| 시간에 따라 변한다 · 범위 | `chart` line · range | 잰 점만 잇는다. 가운데 값이 없으면 뺀다 |
| 누가 무엇을 주고받나 | `flow`(+groups, steps) | 추정·실패 간선을 모양으로 구분 |
| 부르는 순서 · 코드 줄 | `sequence` · `walk` | 주체와 순서가 model의 path와 같게 |
| 조건에 따라 갈린다 | `sim` | 원문의 검사 순서. 뺀 조건은 `scope`에. 모든 조합에 규칙 |
| 겹치거나 앞선다 | `timeline` | 축척이 아니면 "순서만" |
| 전과 후 · 두 선택지 | `compare` | 같은 줄은 `same` |
| 흔한 오해 · 엇갈리는 값 | `predict` | 제목이 답을 먼저 말하지 않는다 |
| 움직여야 뜻이 산다(채움·잘림·돌아옴) | `motion`(MP4) · `motion-inline` | 한 영상에 한 주장 |

- 장마다 "이 그림을 지우면 무엇을 모르게 되나"에 답이 없으면 부품을 바꾸거나 장을 합친다. 아이콘·스톡 사진·뜻 없는 움직임은 쓰지 않는다.
- 같은 부품을 잇달아 세 장 쓰지 않는다. 8장 이상이면 그림 종류 5 · 눌러 보는 장 3 · 모션 2(영상 도구가 있으면 MP4 1) · 견줄 수가 둘 이상이면 차트 1.
- 억지로 채우지 않는다. 수가 없으면 차트를 만들지 않는다. 차트·MP4를 뺀 이유는 `slides.json` 맨 위 `"no_chart":"원문에 비교할 수치 없음"`에 쓴다.

## 글

- 한 장에 한 메시지, 본문 35단어 안팎(제목 포함, 라벨·노트 제외). 제목은 주장하는 문장이고 원문의 조건·확실성을 지킨다.
- 마지막 장을 빼고 장마다 `next`. 다음 장이 그 질문에 답한다.
- 화면에서 뺀 조건·전체 식별자는 `notes`로. 노트에 근거 위치가 붙는다(스크립트).
- 그림의 라벨·순서·움직임도 사실 주장이다. 예시 값이면 화면에 "예시".

## 영상

HTML→MP4 도구(예: `hyperframes`)가 있으면 장면 하나를 6~12초 무음으로 뽑아 `slides/media/`에 mp4와 포스터 jpg로 둔다. 처음과 끝 프레임이 이어지게. 없으면 `motion-inline`. 설치하지 않는다.

## 모양

사용자의 발표 브랜드(스킬·레퍼런스 덱)가 있으면 색·글자·정렬을 그것에 맞춘다(CSS 변수). 없고 `visualize` 스킬이 있으면 그 설계 기준을 읽되 CDN·웹폰트는 쓰지 않는다. 둘 다 없으면 껍데기 그대로.

## 끝내기 전

1. `node scripts/check_slides.cjs <파일>` FAIL 0(puppeteer가 없으면 `render`의 정적 검사까지).
2. `--shots <폴더>`로 찍어 눈으로 본다: 라벨이 다른 화살표에 붙음, 너무 비었거나 빽빽함, 첫 단계가 빈 화면.
