## model
- 참고: RFC·ADR·제안은 `options`가, 발행된 명세·아키텍처 문서는 `flips`가 주인공이다. 한쪽이 없으면 비운다. 원문의 제약을 뒤집어 안을 만들지 않는다.

| 키 | 형 | 개수 | 쓸 것 |
|---|---|---|---|
| options | list{id,t,chosen?,src} | 0–6 | 문서가 실제로 견준 안. 고른 것 `chosen:true` |
| criteria | list{id,t} | 0–4 | 문서가 든 기준. 없으면 `문서가 든 이유` 하나 |
| cells | list{o,c,t,sign:"+\|-\|?",src} | 0–20 | 문서가 말한 칸만. 좋다 +, 나쁘다 -, 조건부 ? |
| flips | list{id,if,then,force?:"필수\|권고\|해도 됨\|서술",edges?,src} | 0–10 | 상황 → 누가 무엇을. 강도는 MUST·SHOULD·MAY 그대로 |
| open | list{t,src} | 0–4 | 문서가 아직 안 정했다고 한 것 |

## 예
**설계 문서 · MCP Streamable HTTP 2026-07-28** — MCP를 HTTP로 주고받는 규칙: 메시지마다 주소 하나에 POST 하나, 답은 그 POST의 응답(JSON 하나 또는 SSE)

**왜** · 본문 값을 헤더에도 적어 중간 장비(로드 밸런서 등)가 본문을 안 열고 나눈다 · 헤더와 본문을 따로 믿으면 보안 구멍이 될 수 있어 서버가 대조한다

```
클라이언트 ─(POST + 본문 값을 옮겨 적은 헤더)▶ 서버
서버 ─(JSON 하나 또는 SSE: 진행 알림 → 최종 답)▶ 클라이언트
```

| 이러면 | 이렇게 |
|---|---|
| 헤더(메서드·이름·버전·도구 인수) ≠ 본문, 필수 헤더 없음 | 본문을 처리하는 서버가 `400` + `HeaderMismatch`(필수) |
| 서버가 입력이 필요 | 먼저 요청하지 않는다. 결과에 입력 요청을 담고, 클라이언트가 답을 붙여 원래 요청을 새 POST로 |
| 클라이언트가 SSE를 닫음 | 그 요청의 취소(서버는 필수). 이어받기 없음 |
| 변경 알림을 받고 싶음 | `subscriptions/listen`의 응답 스트림. 진행 알림은 여기로 안 온다 |
| 서버에 없는 버전 / 메서드 | `400` + 지원 버전 / `404` + `-32601` |
| 클라이언트가 `400`을 받음 | 본문에 새 버전의 오류가 있으면 고쳐서 다시, 비었거나 모르는 오류면 옛 방식 `initialize`(권고) |

**바뀐 것** 없어졌다: GET 스트림(이 개정만 아는 서버는 `405` 권고) · 세션 · 서버가 먼저 보내는 요청

빠진 디테일: `x-mcp-header` 제약과 인코딩 · Origin 검사 · 프록시 버퍼링 · HTTP+SSE 호환 절차 · 대안 비교(원문에 없음)
