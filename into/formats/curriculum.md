# 도메인 전문가 커리큘럼

읽는 사람이 궁금한 것: 다 하면 무엇을 할 수 있나 · 어떤 순서로 하나 · 내가 통과했는지 어떻게 아나

**거꾸로 짠다:** 끝에 할 수 있는 일 → 그것을 보여 주는 증거 → 배울 것.

| 단계 | 칸 | 채울 것 |
|---|---|---|
| 간단히 | 비전 | 끝나면 할 수 있는 **행동** 하나. "깊이 이해한다" 말고 남이 볼 수 있는 일 |
| | 대상 | 지금 수준, 주 몇 시간, 다루지 않는 것 |
| | 졸업 과제 | 비전을 보여 주는 결과물 하나와, 남이 봐도 통과인지 아는 법 한 문장 |
| | 로드맵 | 그림: 입문 → 중급 → 고급 → 심화. 단계마다 질문 하나와 결과물 하나 |
| | 첫 주 | 오늘 시작할 것 하나 |
| 자세히 | 지표 | 2~4개: 무엇이 늘었나 · 어떻게 재나 · 시작 → 목표 |
| | 섹션 | 표: 질문 · 배울 것 · 자료(링크) · 결과물 · 통과 기준 · 시간 |
| | 앞뒤 연결 | 앞 결과물을 어디에 다시 쓰나 |
| 아주 자세히 | 채점표 | 결과물마다. "잘 설명했다" 말고 "라벨 없는 화살표 0개" |
| | 시험 | 처음 점검과 졸업 문제. 같은 난도, 다른 상황 |
| | 실패 사례 | 이 분야에서 실제로 틀린 일과 배운 것, 출처 |
| | 자료 장부 | 자료 · 날짜 · 믿을 정도 · 한계 |

- 그림: 가로 로드맵 한 장.
- 실수: 자료 목록부터 모으지 않는다. 결과물 없는 섹션을 두지 않는다. 링크는 열어 본 것만.
- 참고한 구조: [Understanding by Design](https://en.wikipedia.org/wiki/Understanding_by_Design) — 바라는 결과 → 증거 → 활동
