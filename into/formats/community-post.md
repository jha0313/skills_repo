# 커뮤니티 글 (Reddit · GeekNews · HN …)

읽는 사람이 궁금한 것: 무엇을 물었나 · 의견이 어떻게 갈리나 · 내 경우는 어느 쪽인가

| 단계 | 칸 | 채울 것 |
|---|---|---|
| 간단히 | 한 줄 요약 | 무엇을 이야기했고 어떻게 끝났나. 결론이 없으면 "의견이 갈려요" |
| | 원글 | 원글이 한 말 두 줄. 링크 글이면 그 글도 읽고, 못 읽으면 못 읽었다고 |
| | 입장 지도 | 그림: 입장 3~4개 · 많음/보통/적음 · 한 줄. 읽은 댓글이 몇 개인지 같이 |
| | 입장별 사례 | 입장마다 두 줄: 누가 무엇을 해 봤더니 어떻게 됐다 |
| | 갈리는 이유 | 사람마다 다른 조건이나 바라는 것 |
| | 적용 조건 | 이런 조건이면 이쪽. 셋까지, 글에 나온 조건만 |
| 자세히 | 합의점 | 있을 때만 |
| | 입장별 근거 | 잰 값·경험·말뿐, 그 입장의 대가 |
| | 안 맞는 예 | 입장마다 하나. 찾지 못했으면 그렇다고 |
| 아주 자세히 | 대표 댓글 | 입장마다 대표 댓글 인용 |
| | 읽은 범위 | 몇 개 중 몇 개, 입장별 댓글 수(나눈 기준), 빠진 목소리 |

- 그림: 입장을 나란히. 억지로 승자를 정하지 않는다.
- 실수: 추천 수를 사실로 읽지 않는다. 사람 이름은 꼭 필요할 때만.
- 참고한 구조: 입장별로 근거를 나누고, 합의가 없으면 남겨 두는 토론 요약([LiteMap 연구](https://oro.open.ac.uk/78284) 등. 근거는 작은 연구들)
