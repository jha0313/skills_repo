# PR

읽는 사람이 궁금한 것: 전에는 어땠나 · 지금은 어떻게 되나 · 나는 무엇을 조심하나

| 단계 | 칸 | 채울 것 |
|---|---|---|
| 간단히 | 한 줄 요약 | 누가 무엇을 할 때 무엇이 달라졌나. 구현이 아니라 동작으로 |
| | 왜 바꿨나 | 그대로 두면 일어날 수 있던 일 하나. 본문에 실제 장면이 없으면 `(예시)` |
| | 전 → 후 | **같은 상황 하나**를 두 줄로. 달라진 곳만 표시 |
| | 바뀌지 않은 것 | 바뀌었다고 오해하기 쉬운 것 하나 |
| | 주의할 점 | 쓰는 사람이 겪을 수 있는 일 하나 |
| 자세히 | 동작 순서 | 바뀐 순서 3~5단계 |
| | 상황별 차이 | 표: 상황 · 전 · 후. 같으면 `같음` |
| | 테스트 범위 | 테스트로 확인한 것 / 안 한 것 |
| 아주 자세히 | 파일별 변경 | 파일마다 왜 건드렸나 한 줄 |
| | 대안과 트레이드오프 | 버린 방법, 이 방법의 단점 |
| | 리뷰 포인트 | 파일:줄과 던질 질문 |

- 그림: 위에 전, 아래에 후. 같은 상자는 같은 자리에.
- 실수: 본문은 작성자의 말이고 실제로 바뀐 줄(diff)이 사실이다. 다르면 바뀐 줄을 쓰고 다르다고 적는다.
- 참고한 구조: [Google eng-practices](https://google.github.io/eng-practices/review/developer/cl-descriptions.html) — 첫 줄은 무엇이 바뀌는지, 본문은 왜와 단점
