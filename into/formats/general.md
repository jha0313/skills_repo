# 그 밖 · 에이전트 답

읽는 사람이 궁금한 것: 무엇인가 · 왜 중요한가 · 어떻게 도나

| 단계 | 칸 | 채울 것 |
|---|---|---|
| 간단히 | TL;DR (한 줄 요약) | 한 문장 |
| | 왜 중요한가 | 이것이 없으면 생기는 일 하나 |
| | High-level design (전체 흐름) | 그림: 누가 무엇을 주고받나 |
| | 예시 | 하나를 끝까지 |
| | Insight (놓치기 쉬운 점) | 짐작과 다른 것 하나 |
| 자세히 | Low-level design (한 단계 속) | 그림의 화살표 하나를 확대. 실제 이름과 순서 |
| | 상황에 따라 | 표: 이럴 때 · 이렇게 |
| | Insight 더 | 셋까지. 결과가 뒤집히는 때, 오류 없이 틀리는 것 |
| 아주 자세히 | Low-level design 더 | 남은 화살표 |
| | 묻고 답하기 | 앞 칸에 없는 질문 |
| | 다루지 않은 것 | 이름만 |

- 그림: High-level은 하는 일, Low-level은 실제 이름.
- 실수: 앞 답을 다시 쓸 때 `아마`, `확인 안 됨`을 지우지 않는다.
- 참고한 구조: 실밸개발자의 다섯 칸(TL;DR · 왜 · HLD · LLD · Insights)
