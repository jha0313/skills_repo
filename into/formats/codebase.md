# 저장소

읽는 사람이 궁금한 것: 이게 뭐 하는 건가 · 안에서 누가 무엇을 하나 · X를 하는 코드는 어디 있나

| 단계 | 칸 | 채울 것 |
|---|---|---|
| 간단히 | 한 줄 요약 | 무엇을 받아 무엇을 해 주나. ELI5면 비유 하나 |
| | 전체 구조 | 그림: 상자 3~5개. 폴더 이름이 아니라 하는 일로 |
| | 요청 하나 따라가기 | 요청 하나가 들어와서 나갈 때까지 5단계 |
| | 기억할 것 | 셋까지. 오해하기 쉬운 것부터 |
| 자세히 | 코드 지도 | 표: 하는 일 · 폴더나 파일. "X는 어디 있나"에 답한다 |
| | 상황별 동작 | 표: 이럴 때 · 이렇게. 기본값·실패·한도부터 |
| | 불변 규칙 | 코드가 깨뜨리지 않는 약속(예: 저장은 한 곳에서만) |
| 아주 자세히 | 한 단계 확대 | 위 5단계 중 하나를 파일:줄로 |
| | 공통 관심사 | 설정, 오류 처리, 로그, 권한 |
| | 처음 고칠 때 | 먼저 열 파일, 돌릴 명령 |
| | 안 읽은 곳 | 훑었거나 못 본 부분 |

- 그림: 가는 길은 왼쪽에서 오른쪽, 돌아오는 길은 아래로. 화살표 번호를 `요청 하나 따라가기`의 단계 번호와 맞춘다. 도는 일은 한 바퀴만 그리고 `다시 2번으로`라고 적는다.
- 실수: 폴더 목록을 그대로 옮기지 않는다. 크면 길 하나만 그리고 그렇다고 밝힌다.
