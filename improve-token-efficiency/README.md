# improve-token-efficiency

한 프로젝트의 Claude Code 세션 기록을 모아 토큰과 API 정가 환산 금액을 세고, HTML 한 장으로 보여 주는 스킬이다.

## 언제 쓰나

- "이 프로젝트에서 얼마나 썼지?", "토큰이 어디에 쓰였지?"
- 습관을 바꾼 전과 뒤를 같은 방법으로 비교하고 싶을 때
- 지금 세션이나 구독 한도는 Claude Code의 `/usage`가 더 낫다.

## 설치

```bash
npx skills add jha0313/skills_repo --skill improve-token-efficiency
```

macOS·Linux, Python 3.11 이상. 추가 패키지는 없다.

## 예시 대화

> **사용자:** 이 프로젝트 토큰 효율 분석해 줘.
>
> **에이전트:** 10월 26일~11월 24일, 세션 12개, 환산 $18.40(API 정가 환산, 구독이면 청구액 아님), 캐시 적중 91%.
> 가격을 모르는 응답 3건(4.1K 토큰)은 금액에서 뺐다. 가격표 확인일 2026-11-24.
> 가장 큰 몫은 긴 대화를 다시 읽는 캐시 읽기($7.90)다. 관련 없는 일로 넘어갈 때 `/clear`를 써 보고 다시 재면 된다.
> 보고서: `./token-report/token-report.html`

(숫자는 지어낸 예다.)

## 결과 파일

| 파일 | 내용 |
|---|---|
| `token-report/token-analysis.json` | 합계, 모델별·세션별 토큰과 금액, 점수 |
| `token-report/token-report.html` | 보고서. 외부 요청과 JavaScript가 없다 |

두 파일의 권한은 0600이다. 폴더를 새로 만들 때는 git에 올라가지 않게 `.gitignore`를 함께 넣는다. 프롬프트 본문, 명령, 파일 경로는 넣지 않는다. 세션 id와 프로젝트 이름은 들어 있다.

## 가격표

`references/pricing.json` 하나다. 공식 가격표(`source_url`)에서 확인한 날짜가 `checked_on`에 있고, 90일이 지나면 경고한다. 표에 없거나 `null`인 모델은 금액을 만들지 않고 토큰만 센다.

## 못 하는 것

- 실제 청구액을 알려 주지 않는다. 구독, 계약 할인, 웹 검색 요금, 클라우드 사업자 가격을 모른다. 과거 사용도 지금 가격표로 계산한다.
- 지워진 기록은 세지 못한다. 기본 보존 기간은 30일이다.
- 절감액을 예측하지 않는다. 걸린 크기만 보여 준다.
- Claude Code는 경로의 영숫자가 아닌 글자를 모두 `-`로 바꿔 기록 폴더 이름을 만든다. 그래서 `my_app`과 `my-app`은 기록 폴더를 함께 쓴다. 기록의 `cwd`로 갈라 다른 프로젝트 응답과 어느 쪽인지 모르는 응답은 합계에서 빼고 건수를 따로 보여 준다. `--repo` 없이 `--sessions-dir`만 주면 가르지 않고 모두 센다.
- worktree와 하위 폴더에서 연 세션은 다른 기록 폴더에 있다. 따로 돌린다.
- 기록 형식은 공개 규격이 아니다. Claude Code가 바뀌면 고쳐야 한다.
- Windows에서는 확인하지 않았다.
