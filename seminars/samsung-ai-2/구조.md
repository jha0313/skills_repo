- 32장 고정. PM·adoption 모듈은 제외한다. 신규26–30의 개인 경험30분은 각6분의 짧은 경험·도식·청중 질문으로 진행한다.

## 장별 구성

### Slide 1: 한마디

**Intro · 1분**

핵심: 코드 구현을 넘어 workflow를 맡기고, 결과를 믿을 근거를 받자.

- 구현을 맡기는 것에서, 업무의 흐름을 맡기는 것으로
- 위임의 범위는 넓게 · 완료의 근거는 분명하게

화면: 표지의 핵심 문장만 강조한다.
발표자 메모: 아직 설명하지 않은 도구 이름을 한꺼번에 나열하지 않는다.

### Slide 2: 소개

**Intro · 1.5분**

핵심: 만들고, 쓰고, 고객인 개발자의 경험을 나눈다.

- WashU 전기공학·컴퓨터사이언스 복수전공 → CS 석사
- Morningstar → Meta · 개발 생산성 업무
- YouTube·온라인 강의 · 직접 만들고 쓰는 AutoKliq

화면: 기존 소개 마스터의 경력·제품 카드만 가리킨다.
발표자 메모: 기존 자료의 구독자 수·604 커밋·경력 연차를 현재 통계로 갱신 추정하지 않는다.

### Slide 3: 오늘 다룰 문제와 내용 소개

**Intro · 2.5분**

핵심: 더 많이 생성한 뒤에는, 더 많이 확인하고 관리하게 된다.

- AI 도입 뒤 흔히 늘어나는 일: 결과 검증·재작업 / 새 기능·활용법 학습 / 동시 업무 관리
- 구현이 빨라져도 확인과 관리는 남는다
- 오늘: Agentic Workflow → AutoKliq / AI Eval → skill-evaluator

화면: 늘어나는 일 세 가지를 차례로 강조한 뒤 두 파트·두 데모를 보여준다.
발표자 메모: 공개판은 내부 설문 수치와 원문을 담지 않는다. 세 항목은 정성적 문제 소개이며 특정 조직의 실측 통계로 말하지 않는다.

### Slide 4: why agentic workflow

**Part 1: Agentic Workflow · 2분**

핵심: 구현 앞뒤의 병목까지 맡겨야 업무 전체가 빨라진다.

- 구현 속도는 올라갔다
- 일을 설명하고, 끝난 일을 검수하는 과정이 새 병목
- Agentic workflow: 에이전트가 문제를 푸는 방식

화면: 구현 앞·뒤의 대기 구간을 강조한다.
발표자 메모: 자동화 범위 확대를 무제한 권한으로 설명하지 않는다.

### Slide 5: what is agentic workflow

**Part 1: Agentic Workflow · 2분**

핵심: 각 단계가 다음 단계에 넘길 결과를 정한다.

- Intake → Context → Plan → Implement → Verify → Land & Monitor
- 입력 → 맥락 → 계획 → 변경 → 증거 → 관측·환류

화면: [INTERACTIVE] 단계 버튼을 눌러 설명 전환. 6단계 흐름을 한 칸씩 강조하고 Monitor에서 Context로 돌아가는 화살표를 짚는다.
발표자 메모: Review는 Verify와 Land의 경계에서 다룬다. 별도 새 슬라이드를 추가하지 않는다.

### Slide 6: Intake

**Part 1: Agentic Workflow · 2분**

핵심: 티켓과 대화를 에이전트가 읽을 작업 계약으로 만든다.

- Task / Ticket: 목표·제약·위험·가정·성공 조건
- 회의·coffee chat의 결정도 Markdown으로
- 사실과 미확인 가정을 구분한다

```yaml
goal: 추천을 채택한 이유와 제작 결과를 연결한다
constraints:
  - 기존 생성 계약을 보존한다
  - 이번 범위에서 운영 DB를 변경하지 않는다
assumptions:
  - 기존 프로젝트에 출처를 연결할 수 있다: 확인 필요
success_checks:
  - 저장 후 재진입해도 선택 이유가 남는다
```

화면: 티켓 예시의 goal / constraints / assumptions / success_checks를 순서대로 짚는다.
발표자 메모: 확인하지 않은 가정을 사실로 적지 않는다.

### Slide 7: Context

**Part 1: Agentic Workflow · 3분**

핵심: 팀 지식을 rules·skills로 만들고 team plugin으로 묶는다.

- Team / Codebase Knowledge → Rules · Skills → Team Plugins
- 공통 원본 + 얇은 AGENTS.md / CLAUDE.md 연결
- name · description · oncall · apply_to_path · apply_to_content

```yaml
name: thumbnail-input-contract
description: 썸네일 제작 입력과 적용 시점의 규칙
oncall: creator-tools
apply_to_path:
  - src/thumbnail/**
apply_to_content:
  - brief
  - generationInput
```

화면: [INTERACTIVE] 메타데이터5필드를 눌러 규칙 줄 강조. 아래 rule 예시를 화면에 표시한다. 각 필드는 한 번씩만 설명한다.
발표자 메모: 제공 메모의 Meta 1,500+ team plugins는 특정 시점 내부 사례이며 공개 검증 통계·효과 측정치가 아니다. 필요하면 말로만 덧붙인다.

### Slide 8: Plan

**Part 1: Agentic Workflow · 3분**

핵심: 깊게 인터뷰하고, 구현 전에 계획과 성공 조건을 리뷰한다.

- Deep interview: 목적·제약·트레이드오프
- Non-trivial task: 구현 전에 Human / LLM-as-judge plan review
- Success checks를 계획에 포함

화면: 질문 → 계획 → 리뷰 → 구현 순서와 성공 조건 한 줄을 강조한다.
발표자 메모: “첫 번째로 권하는 생산성 팁”은 발표자의 우선순위다. 보편적 효과 순위나 검증된 배수로 말하지 않는다.

### Slide 9: Implement

**Part 1: Agentic Workflow · 3분**

핵심: 합의한 계획·권한 안에서 AI가 구현을 진행한다.

- 중간 코딩 개입 없이, 합의한 계획대로 실행
- Subagents / Agent Teams: 역할과 작업 병렬화
- Worktree: 동시 변경의 작업 공간 격리

화면: 작업자 카드와 분리된 worktree를 보여주고 통합 담당에 연결한다.
발표자 메모: Worktree는 의미 충돌·공유 DB·포트 충돌까지 없애주지 않는다.

### Slide 10: Verify

**Part 1: Agentic Workflow · 4분**

핵심: GATE 통과와 실제 정답을 구분한다.

- GATE: lint · build · unit tests — cheap / deterministic / hook
- Passing GATE ≠ correctness
- VERIFY: 실제 결과·ground truth·도메인 검증
- AI review: 저위험 자동화 / Human review: 위험 diff·구조·비즈니스 로직

화면: [INTERACTIVE] 낮은/높은 위험을 눌러 리뷰 경로 전환. GATE/VERIFY 두 열을 먼저 보여준 뒤 AI/human 역할과 위험 분류를 강조한다.
발표자 메모: 50%+와 24h 추세는 사용자 제공 내부 관찰이다. 생산성 50% 향상으로 바꾸지 않는다. Auto-land도 기존 권한·브랜치 보호를 따른다.

### Slide 11: Land & Monitor

**Part 1: Agentic Workflow · 1.5분**

핵심: 끝난 업무에서 배운 것을 다음 업무의 규칙으로 남긴다.

- 반영한 revision과 실제 관측을 연결
- 발견한 문제 → lint / rule / eval
- 다음 작업에서 같은 실수를 줄인다

화면: Monitor → Context 환류 화살표를 짚는다.
발표자 메모: PR 제출·CI 확인을 merge·배포·운영 모니터링과 섞지 않는다.

### Slide 12: Oncall

**Part 1: Agentic Workflow · 3분**

핵심: 장애에서는 영향 완화와 원인 분석을 병행한다.

- 1.a Mitigation: 되돌릴 수 있는 완화 · feature flags
- 1.b RCA: SEV 생성 약 15분 뒤 자동 분석·원인 후보
- 2 Investigation → 3 SEV Report / 필요하면 Deep Debugging

화면: Mitigation과 RCA 두 갈래를 동시에 강조한 뒤 조사·보고로 합친다.
발표자 메모: 15분은 사용자 제공 운영 사례의 분석 시점이며 MTTR이나 보편적 SLA가 아니다. Flag 후보 제안과 실제 변경 권한을 구분한다.

### Slide 13: Demo (autokliq)

**Part 1: Agentic Workflow · 8분**

핵심: 실제 대화에서 계획·병렬 구현·검증이 이어지는 장면을 본다.

- 대표: 채널 프로듀서 작업실 — 추천 출처와 결정 기록을 제작으로 연결

- 기록 당시 PR #80 + CI / 대표 사례의 merge·운영 배포 미수행
- 짧은 대안: 썸네일 UI/UX — PR #81

화면: [INTERACTIVE] 원본 영상 재생·일시정지 /6개 단계 버튼으로 실제 메인 발췌·해설. 슬라이드 안의 원본79초 채널 프로듀서 영상과 workflow timeline·메인 기록 발췌를 사용한다. PR80 링크는 근거용이다. 짧은 대안은 기존25초 썸네일 영상이다. 차단된 리플레이 페이지를 다른 경로로 열지 않는다.
발표자 메모: 주 사례 PR80은 OPEN. 대안 PR81은 녹화 이후 다른 세션에서 MERGED됐다. 기록과 현재 상태를 구분한다. 차단된 리플레이 UI는 열지 않고 deck 안의 원본 영상·발췌·timeline을 사용한다.

### Slide 14: Tips

**Part 1: Agentic Workflow · 1.5분**

핵심: 큰 효과를 만드는 두 축은 Context engineering과 Parallelism이다.

- Context engineering: rules · skills · team plugins
- Parallelism: worktrees · Agent Teams · background / CI-offloaded agents

화면: 두 축의 카드에서 방금 데모 장면 하나씩 연결한다.
발표자 메모: 효과 순위는 제공된 현업 관찰이며 모든 팀의 검증된 보편 순위가 아니다.

### Slide 15: Recommended starting workflow

**Part 1: Agentic Workflow · 2분**

핵심: 팀 맥락 하나와 성공 조건 하나부터 시작한다.
