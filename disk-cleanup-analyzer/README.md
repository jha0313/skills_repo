# disk-cleanup-analyzer

맥에서 용량을 차지하는 것을 찾아 정리 계획을 만든다. **AI 코딩 세션의 작업 폴더를 실수로 지우지 않게 판정하는 것**이 이 스킬의 값이다.

> macOS 전용. 스크립트는 읽기만 한다. 삭제는 에이전트가 항목마다 묻고, 승인한 것만 한다. 이 규칙은 지침이다. 에이전트의 다른 명령까지 막아 주지는 않으니 실행 권한은 직접 확인한다.

## 왜 필요한가

여러 AI 세션을 열어 두면 `/private/tmp/claude-<uid>/` 아래에 작업 폴더가 쌓인다. 이름에 tmp가 있어 쓰레기처럼 보이지만 하나뿐인 원본이 들어 있을 수 있다. 며칠 쉬는 세션은 파일을 잡고 있지 않아 `lsof`로도 찾기 어렵다. 이 스킬은 실행 중인 프로세스의 작업 디렉터리, 대화 기록과 파일의 마지막 수정 시각, 원본처럼 보이는 파일을 함께 본다. 하나라도 확인하지 못하면 지킨다(KEEP).

| 판정 | 뜻 |
|---|---|
| KEEP | 열려 있거나 최근에 썼거나 확인하지 못했다. 제안하지 않는다 |
| REVIEW | 오래 쉬었지만 원본일 수 있는 파일이 있다(캐시 폴더 안 포함). 옮길지 묻는다 |
| ASK | 오래 쉬었고 도구가 만든 출력·바이트코드·빈 파일뿐이다. "지워도 됨"이 아니라 "물어볼 수 있음"이다 |

## 설치

```bash
npx skills add jha0313/skills_repo --skill disk-cleanup-analyzer
```

Python 3.9 이상(macOS 개발 도구에 든 `python3`로 된다). herdr(에이전트용 터미널 멀티플렉서)를 쓰면 열린 패널도 본다. 없어도 된다.

## 예시 대화

```text
나: 맥북이 꽉 찼어. 뭐부터 정리하지?
에이전트: 여유 11.8 GB. 1 GB 넘는 것 9개를 나눴습니다. 아직 아무것도 지우지 않았습니다.
  ① 다시 만들어지는 캐시: ~/.npm/_cacache 6.1 GB, 마지막 수정 어제, 다음 설치 때 다시 받음
  ② 검토: 시뮬레이터 14.0 GB (안의 앱 데이터가 사라짐)
  세션 폴더: KEEP 5 · REVIEW 1(scratchpad/site/index.html) · ASK 1(820 MB, 12일 전)
  항목마다 물을게요. npm 캐시를 지울까요?
나: 응, 그것만.
에이전트: 다시 쟀고 값이 같습니다. npm cache clean --force → 여유 11.8 → 17.6 GB
```

(숫자는 지어낸 예다.)

스크립트만 써도 된다.

```bash
# 이 스킬 폴더에서 실행한다
python3 -I scripts/scan.py            # 홈과 /Library의 큰 폴더·파일
python3 -I scripts/session_dirs.py    # 세션 폴더 판정
python3 -I scripts/scan.py --record <경로> > 기록.json   # 승인받을 때의 경로·크기·하위 목록
python3 -I scripts/scan.py --check 기록.json             # 지우기 직전 대조 (0 같음, 1 달라짐, 2 확인 못 함)
python3 tests/run_tests.py            # 임시 폴더와 가짜 ps·lsof·herdr로 검사
```

## 못 하는 것

- Claude Code 말고 다른 에이전트(Codex, Cursor 등)의 작업 폴더는 판정하지 못한다. 그래서 후보에 넣지 않는다.
- 판정은 Claude Code의 폴더 이름 규칙과 `ps`·`lsof` 출력에 기댄다. 규칙이 바뀌면 대개 "대화 기록 없음"으로 KEEP이 되지만, 모든 경우에 맞다고 보장하지 않는다.
- 다른 폴더에서 도는 백그라운드 세션은 최근 활동(기본 7일)으로만 걸린다.
- 대화 기록이 이미 지워진 오래된 폴더는 KEEP으로 남는다. 세션이 열린 프로젝트의 옛 세션 폴더도 KEEP이다. 놓치는 것보다 남기는 쪽을 골랐다.
- 도구가 만든 것으로 확인한 파일만 뺀다. `.log`·`.out`·`.tmp`나 `node_modules`·`.cache` 안의 파일도 원본일 수 있다고 보므로, 이런 것이 남은 세션은 REVIEW다.
- `--check`는 하위 항목의 경로·종류·크기·수정 시각을 대조한다. 이것을 다 그대로 두고 내용만 바꾼 것, 대조한 뒤 지우기 전에 바뀐 것은 못 잡는다.
- 표의 크기와 실제 회수량은 다를 수 있다(APFS 복제·스냅샷, 하드 링크).
- 예약 실행 스크립트는 없다. 비대화형으로 돌리면 에이전트의 권한 설정에 따라 스캔 명령이 막힐 수 있다. 돌리더라도 보고서까지만 쓴다.
- 세션 제목을 찾으려고 대화 기록을 읽는다. 본문은 출력하지 않지만 제목이 보고서에 남는다.
