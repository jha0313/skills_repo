# time-convert

시각을 다른 시간대로 바꿀 때 AI가 암산하지 않고 스크립트로 계산하게 한다. 출력은 한국어다.

## 왜 필요한가

AI는 시차를 외운 값으로 답하다가 서머타임이 바뀌는 주에 한 시간씩 틀린다. 요일을 하루 틀리거나, 존재하지 않는 시각(시계가 앞으로 가는 새벽)을 약속 시간으로 제안하기도 한다. 이 스킬은 계산을 `when.py`에 맡기고, 애매하면 멈춰서 묻게 한다.

- 여러 도시를 한 번에, 요일과 전날·다음 날 표시
- 시차가 바뀌는 날, 두 번 오는 시각, 없는 시각 표시
- 적은 요일이 날짜와 다르면 경고
- 서머타임을 건너는 남은 시간(벽시계 차이가 아니라 실제로 흐르는 시간)
- 다 읽지 못한 입력은 짐작하지 않고 오류(`14:00 PST`의 `PST` 등)

## 설치

```bash
npx skills add jha0313/skills_repo --skill time-convert
```

Python 3.9 이상. 외부 패키지와 네트워크를 쓰지 않는다.

자주 쓰는 도시는 환경 변수로 둔다(선택). 없으면 이 컴퓨터의 시간대와 [IANA 이름](https://www.iana.org/time-zones)만 쓴다.

```bash
export WHEN_PLACES="서울=Asia/Seoul,런던=Europe/London"
```

## 예시 대화

```text
나: 2025년 3월 20일 로스앤젤레스 오전 9시 회의, 런던이랑 서울은 몇 시야?
에이전트: (when.py "2025-03-20 09:00" --from America/Los_Angeles --to Europe/London,Asia/Seoul)
  America/Los_Angeles: 2025-03-20(목) 09:00 (UTC-7)
  Europe/London: 2025-03-20(목) 16:00 (UTC+0)
  Asia/Seoul: 2025-03-21(금) 01:00 (UTC+9, 다음 날)
나: 4월 10일이면?
에이전트: 런던은 17:00입니다. 3월 20일에는 미국만 서머타임이어서 한 시간 달랐습니다.
```

직접 돌리기와 시험(`time-convert` 폴더에서):

```bash
python3 -I scripts/when.py "금 오후 1시" --from Asia/Seoul --to 여기,UTC
python3 -I scripts/when.py now --to Asia/Seoul --json
python3 tests/run_tests.py
```

종료 코드: 0 정상, 2 입력을 못 읽음, 3 경고가 있음(결과와 함께 나온다. 없는 시각이면 결과가 비어 있다).

## 못 하는 것

- 시간대 규칙은 컴퓨터의 시간대 자료를 따른다. 자료가 낡았거나 나라가 규칙을 바꾸면 앞날의 결과가 틀릴 수 있다.
- 약자(EST, KST 등)는 받지 않는다. 뜻이 여럿이거나 고정 시차로 계산되기 때문이다. 원하면 `WHEN_PLACES`에 직접 정한다.
- 연도를 안 적으면 올해로 본다. 12월에 "1/5"라고 쓰면 이미 지난 1월이다. 가정과 남은 시간("전")에 드러난다.
- "다음 주 금요일", 시간 범위, 초, 반복 일정, 공휴일은 읽지 않는다.
- 별칭 때문에 생긴 오해는 잡지 못한다. 별칭 값은 사용자가 확인한다.
